# 官方行程编写规范（草案）

日期：2026-10-15。状态：草案，待评审。用途见 [智能规划重构：第一版规格](smart-planning-rebuild.md)。

App 的智能规划原样展示官方方案，不改写也不补写。所以方案写成什么样，用户就看到什么样。本规范约定方案的结构、字段和写法，人工编写和 AI 起草都按它执行。

## 1. 官方方案是什么

- 官方团队设计并核实后推荐的走法。它不是游记转写：作者个人的安排（比如因为订好的航班多住一天）不能写成方案的一部分。
- 有进山日时，从县城、机场、火车站这类交通方便的地方开始写；有出山日时，同样写到这类地方为止。从用户所在城市过来和回去的大交通不写进逐日。
- 一条线路可以有多个方案，但只有天数、方向或住宿方式不同时才拆分。其余差异（例如营地选择略有不同）合并成一个方案，写进官方提示。
- 每条线路标一个默认推荐方案。
- 线路攻略的其他章节（概览、交通、费用、季节与风险等）继续按原格式维护，用于展示和问答。逐日行程以官方方案为准。

## 2. 关键概念

**进山口和出山口：** 开始和结束步行的地方，例如格聂牧场线的下则通村、则巴村。

方案不单独填写"从哪里出发、到哪里结束"，逐日内容已经说明了。

**天的类型：**

| 类型 | 定义 | 例 |
| --- | --- | --- |
| 进山日 | 从县城、机场等地到进山口附近过夜，当天不徒步 | 理塘 → 下则通村 |
| 徒步日 | 当天有任何徒步；接驳可以出现在当天开头或结尾 | 夯达营地 → 则巴村，再拼车回理塘 |
| 休整日 | 不移动营地，为所有人都需要的理由而停留 | 高海拔适应 |
| 出山日 | 从出山口回到县城、机场等地，当天不徒步 | 则巴村 → 理塘 |

规则：

- 进山日和出山日只能出现在首尾。用户可以在预览时整体去掉，所以去掉后的方案也必须能走通。
- 休整日要写明理由，而且这个理由对所有人都成立。可选的多停留不加天，写进前一天的官方提示，例如"天气好可在蛇湖多留一天"。
- 方案名里的天数是含进出山日的总天数。

## 3. 方案级字段

| 字段 | 必填 | 说明 | 例 |
| --- | --- | --- | --- |
| 方案名 | 是 | "N 天 M 晚" + 住宿方式 + 走法 | 4 天 3 晚扎营穿越（下则通村至则巴村） |
| 方向 | 单向线路必填 | 起点至终点 | 下则通村至则巴村 |
| 住宿方式 | 是 | 扎营、住宿、混合 | 扎营 |
| 强度 | 是 | 见第 7 节 | 中高 |
| 适合人群 | 是 | 一句话 | 有多日扎营经验 |
| 方案说明 | 是 | 150 字以内：怎么走、最难的是哪天 | 见第 9 节 |
| 注意事项 | 否 | 最多 5 条，每条 40 字以内 | 费用不含餐食、驮包和摩托车接驳 |
| 推荐月份 | 否 | 不填则沿用线路的推荐月份 | 5～10 月 |
| 季节说明 | 否 | 不填则沿用线路的季节说明 | 6～7 月花海最佳 |

## 4. 逐日字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 类型 | 是 | 进山、徒步、休整、出山 |
| 标题 | 是 | 起点 → 终点，中间最多列 3 个关键节点 |
| 距离、爬升、下降 | 徒步日应填 | 距离 km，爬升和下降 m 取整 |
| 预计用时 | 否 | 例如 6～8 小时 |
| 接驳 | 进山日和出山日必填；徒步日有接驳时填 | 起点、终点、方式（包车、拼车、班车、景区观光车）、时长、费用参考、预约要求 |
| 住宿 | 最后一天以外必填 | 名称、类型（营地、民宿、客栈、酒店）、海拔、水源、费用参考、手机信号 |
| 补给 | 否 | 沿途或营地能买到什么 |
| 官方提示 | 否 | 100 字以内：关键风险、出发时间建议、可选的多停留 |
| 下撤点 | 否 | 名称和说明 |

## 5. 数字和事实

- 写官方核实过的数值。可以写约数（"约 15 km"），但不写"原文记""作者所述""信息日期不详"一类的来源措辞。
- 不确定的字段留空，App 会显示"未收录"或不显示。不要用推算值填空，例如把总距离按天数平分。
- 距离和爬升以官方走法为准。与目录轨迹不一致时，在方案说明里写明差异。
- 逐日距离之和要能和全程距离对上；对不上时先查清，再发布。
- 价格、接驳等易变信息写"参考"，以核实日期为准；不写具体发车时刻和电话。
- 建议在每个旺季前复核一次易变信息。

## 6. 写法

- 中文，陈述句，不用第一人称，不出现"作者""原文"。
- 不用 `·` 作分隔，用空格、逗号或顿号。
- 地名与目录轨迹的标注点一致，同一地点全文只用一种写法。
- 每天的起点和终点用"→"连接；时间区间、月份区间用"～"。

## 7. 强度

暂时沿用目录线路的四级：易、中、中高、高。方案的强度按该方案最难的一天评定，所以同一线路的短方案可能比长方案更高。具体判定标准待官方补充。

## 8. 审核与发布

- 状态：草稿 → 待审核 → 已发布 → 已归档。
- AI 起草的方案标为"AI 起草"。每个数字和事实在草稿元数据里附来源（素材编号或链接），不对用户展示；没有来源的字段留空。
- 发布条件：必填字段齐全，核实人逐项确认，填写核实人和核实日期。
- 修改已发布的方案会生成新版本。用户已保存的旅程不会跟着变化。

与采集稿相比做了这些设计决定，请重点审：

1. 成都到理塘属于大交通，从 Day 1 拿掉；方案从理塘县城出发，最后回到理塘县城。
2. Day 4 有 2 km 步行，按规范算徒步日，出山接驳挂在当天；因此这个方案没有单独的出山日。
3. 原文的发车和到达时刻（06:30 出发、08:30 乘车等）不写，只保留"建议 08:00 前出发"这类建议。
4. 推荐月份的两个来源不一致，暂时沿用目录，待官方定。
5. 距离对不上：逐日相加 32 km，原文概述约 30 km，目录 GPX 为 28.2 km。按第 5 节，发布前要查清。
6. 第 2 天的下降、第 3 天的爬升和下降、各天用时都未收录，留空。
7. 理塘回成都的拼车提醒属于大交通，不写进注意事项。

## 10. 数据格式（`route_itineraries.payload`）

字段名用英文，与第 3、4 节一一对应。所有字符串都不能含 `·`；未收录的字段写 `null` 或省略，不写空字符串。

```jsonc
{
  "name": "4 天 3 晚扎营穿越（下则通村至则巴村）", // 方案名，1～40 字
  "direction": "下则通村至则巴村",                  // 方向，可为 null
  "lodging": "camp",                               // camp 扎营 | lodge 住宿 | mixed 混合
  "difficulty": "中高",                            // 易 | 中 | 中高 | 高
  "audience": "有多日扎营经验",                     // 适合人群，1～40 字
  "summary": "……",                                 // 方案说明，1～150 字
  "notes": ["费用不含餐食、驮包和摩托车接驳"],        // 注意事项，0～5 条，每条 1～40 字
  "bestMonths": null,                              // 推荐月份 1～12 的数组；null 表示沿用线路
  "seasonNote": null,                              // 季节说明；null 表示沿用线路
  "days": [                                        // 1～30 天
    {
      "kind": "access_in",                         // access_in 进山 | hike 徒步 | rest 休整 | access_out 出山
      "title": "理塘 → 下则通村",                    // 1～80 字
      "distanceKm": null, "ascentM": null, "descentM": null, // 数字或 null；爬升、下降为整数
      "duration": null,                            // 预计用时文字，例如 "6～8 小时"
      "transfers": [                               // 接驳；access_in / access_out 至少一条
        { "from": "理塘", "to": "下则通村", "mode": "shared", // charter 包车 | shared 拼车 | bus 班车 | shuttle 景区观光车
          "duration": null, "costRef": "60 元/人", "booking": null,
          "position": "start" }                    // start 当天开头 | end 当天结尾
      ],
      "stay": {                                    // 除最后一天外必填；最后一天可为 null
        "name": "下则通村", "type": "homestay",     // camp 营地 | homestay 民宿 | inn 客栈 | hotel 酒店
        "altitudeM": null, "water": null, "costRef": "民宿床位 70 元/人，扎营免费", "signal": null
      },
      "supply": null,                              // 补给
      "tip": null,                                 // 官方提示，0～100 字
      "bailout": null,                             // 下撤点
      "source": "official"                         // official | kb_generated | user_track（第一版只有 official）
    }
  ]
}
```

结构规则：

- `access_in` 只能连续出现在开头，`access_out` 只能连续出现在结尾；去掉它们后至少剩 1 天。
- `access_in` 和 `access_out` 的天不能有 `distanceKm`。
- `rest` 的天必须有 `tip` 说明理由。

AI 起草的草稿另附 `draft_sources`（不对用户展示）：`[{ "path": "days[1].distanceKm", "ref": "trk014.md#s1" }]`，每个非 null 的数字和费用都要有一条。
