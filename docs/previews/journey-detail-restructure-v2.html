批次建议

批次内容依赖为什么这样排
P0四个标签和连续的行程页；计划概览；每日天气；轨迹只读并能跟着走；走完的记录自动挂回旅程；离线就绪都已有现成能力：trailRouteFromPoi、useRouteWeather、OfflineMapRow、TrackDetailPage只是把已有能力接进来，没有新数据；做完以后这个页面才是「去走」的页面
P1阶段化总览（准备、今天、回顾）；发起人和同行人视角；集合信息；公用装备分工；路线近况；最晚折返时间；水源和营地提示；个人配速集合时间地点和公用装备负责人需要新字段；路标需要可靠的类型（水、补给、营地）差异化主要在这一批；折返时间是行业里少见的
P2行程报备和超时提醒；家人网页；按近况和天气调整清单；装备复盘；游记服务端定时任务、短信、网页访客端扩展价值高，但新后端最多，安全相关的文案和边界要单独评审
不做聊天、大交通和住宿预订、AA 记账—微信已经占住沟通；智能规划 v1 定了不做大交通；记账和「走好这条路」关系不大
