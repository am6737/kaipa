# Kaipa 后台管理骨架

## 当前阶段

本目录实现的是后台信息架构与交互原型，不是生产管理端。所有记录、服务指标、角色和配置均为 mock；没有调用管理 API、发送通知或邀请邮件、修改数据库或执行运维任务。

- 入口：`http://localhost:8092/admin-preview.html`。
- 模块地址：`#/routes`、`#/settings` 等，支持刷新定位和浏览器前进、后退。
- 跨模块筛选：例如 `#/content?q=C-807`。
- 模拟修改在当前 React 会话内保留；刷新或右上角“重置模拟数据”恢复初始数据。
- 当前身份固定为超级管理员；角色权限页编辑的是模拟权限配置，不是实际的授权机制。
- 仪表盘汇总和趋势为独立示例统计，不等于列表中少量样本的合计。待审核、举报和最近操作从当前 mock 记录计算。

## 信息架构

| 分组 | 模块 | 当前骨架 | 真实接入边界 |
| --- | --- | --- | --- |
| 工作台 | 数据概览 | 时间范围、趋势、待办跳转、最近行程与操作 | 聚合接口、统计口径和时区 |
| 业务数据 | 用户管理 | 账户摘要、搜索、停用与恢复 | `profiles` 与独立的管理账户接口；不暴露敏感规划资料 |
| 业务数据 | 行程管理 | 行程摘要、成员与清单信息、版本保留说明 | `journeys`、`companions`、packing、versions；默认只读，不代替成员修改私人行程 |
| 业务数据 | 路线资源 | 新建与编辑草稿、发布、下架 | 现有 `routes` 外，需要新增平台资源归属、审核状态和编辑版本 |
| 业务数据 | 公共装备库 | 品牌、分类、重量、草稿和发布流程 | 新的平台公共资源模型，不复用个人 `gear_items` 作为运营库 |
| 业务数据 | 清单模板 | 场景、条目、编辑、发布和下架 | 从 `recommendedPackingTemplates` 的本地推荐数据迁移到版本化模板模型 |
| 运营与安全 | 内容审核 | 审核、驳回、已通过内容下架 | 公开灵感和分享资源；新增审核队列和审核记录 |
| 运营与安全 | 举报处理 | 待处理、处理中、关联内容、结案原因 | 新增举报工单；结案不自动下架内容，内容动作应单独授权与记录 |
| 运营与安全 | 用户反馈 | 分类、处理进度、回复、标记解决 | 新增反馈工单与回复记录 |
| 运营与安全 | 通知公告 | 人群、渠道、草稿、发布、撤回 | 新增公告与发送任务，不把现有每用户 `notifications` 表等同于群发系统 |
| AI 与系统 | AI 执行记录 | 结果、耗时与 token 示例、工具摘要 | `agent_runs`、`agent_tool_calls`；对话和个人资料需脱敏与单独授权 |
| AI 与系统 | 服务状态 | 自托管 API、存储、函数、备份快照、异常请求跳转 | 独立监控接口；不在浏览器内持有运维凭据或运行部署命令 |
| AI 与系统 | 系统配置 | 基础信息、分享审核开关、AI 限额与超时 | 配置服务、校验、版本、回滚、运行时生效范围 |
| 组织管理 | 管理员 | 模拟邀请、编辑成员角色、停用恢复、自身账户保护 | 独立后台身份、邀请凭证、MFA、会话撤销 |
| 组织管理 | 角色权限 | 固定角色的权限矩阵、保存与放弃修改 | 服务端 RBAC；当前页面不模拟权限拦截，身份固定为超级管理员 |
| 组织管理 | 操作日志 | 新增、编辑、状态变更、导出与配置变更记录 | 服务端不可篡改审计，记录操作者、目标、前后值与请求 ID |

## 公共交互

- 列表：搜索名称、归属人或编号，状态筛选及数量、时间排序、紧凑行距、分页、导出全部或当前筛选结果。
- 详情：字段分组、图片、上一条和下一条、关联模块跳转。
- 表单：必填项、邮箱、数字范围校验；新公共资源进入草稿状态。
- 变更：发布与审核有确认步骤；停用、下架、驳回和举报结案必须填写原因。
- 审计：模拟管理动作联动操作日志；日志列表本身没有编辑或删除入口。
- 辅助能力：明暗模式、移动端导航、键盘焦点约束、Escape 关闭、空结果、反馈提示、模拟数据重置。
- CSV：转义引号，并处理以公式字符开头的单元格。

## 代码边界

- `src/web/admin/AdminMock.tsx`：应用壳、hash 路由、会话内状态与管理动作协调。
- `adminModules.ts`：导航分组、模块字段、状态动作和扩展示例数据。
- `mockData.ts`：记录类型与原始业务样本。
- `AdminTable.tsx`：后台公共列表与 CSV 导出。
- `AdminDialog.tsx`、`AdminRecordForm.tsx`：详情容器、焦点管理和字段驱动表单。
- `ResourceEditor.tsx`、`ChecklistEditor.tsx`、`resourceEditorModel.ts`：路线、装备、模板专用编辑器，结构化途经点与装备条目、校验与实时预览。
- `resourceVersions.ts`、`ResourceVersionsPanel.tsx`：草稿与发布快照、字段差异、发布历史及追加式回滚。
- `AdminOverview.tsx`、`TrendChart.tsx`：模拟概览与趋势。
- `AdminSettings.tsx`：配置表单与角色矩阵。
- `AdminAccount.tsx`：当前管理员资料、安全状态、个人偏好与模拟退出入口。
- `AdminInbox.tsx`、`adminInboxModel.ts`：个人通知、分配待办、关联业务状态与 UTC 截止时间。
- `TaskCollaboration.tsx`、`taskCollaborationModel.ts`：负责人、协作者、计划调整、留言、追加式历史与会话内版本校验。
- `TaskBatchPanel.tsx`、`taskBatchModel.ts`：批量执行预览、整体校验、批量分配、逾期提醒及重复提醒限制。
- `adminStyles.ts`：后台 Web 样式，颜色和基础 token 从现有 Theme、公共 design-system API 注入。

当前通用记录结构只适合原型。真实接入应按用户、路线、公共装备、模板、工单等定义领域 DTO 和对应 repository，不将所有业务永久存入同一种表结构。

## 资源编辑体验

- 路线支持里程、爬升、时长、类型、起终点、季节、提醒与有序途经点。途经点是运营内容，不是坐标轨迹；本轮未实现 GPX/KMZ 解析或地图绘制。
- 装备支持品牌、型号、重量、参考价、材质、容量、尺寸、睡眠类温标。
- 模板使用 `checklistItems` 结构化条目，支持公共装备添加、自定义条目、数量、单件重量、分类、必带标记、上下移动和单次删除撤销。已添加的装备保留快照，后续装备库修改不会自动覆盖模板。
- 模板原有纯文本条目在编辑时迁移，未知分类记为“其他”，未知重量记为 `null`；汇总同时提示未填写重量的条目数。
- 图片可选择示例封面或读取本地 JPG/PNG/WebP（最多 2 MB），校验可解码后仅保存在本次会话；没有上传服务。日志用占位标记替代本地图片内容。
- 桌面显示并排预览，手机在编辑与预览间切换；底部固定保存操作。保存含字段级校验，离开有未保存修改的资源编辑器时需要确认。
- 已发布资源可创建修订草稿，保存不改变当前发布内容；也可“复制为草稿”，副本使用独立 ID，不继承发布历史。

## 资源发布与版本

- 路线、公共装备和清单模板共用版本流程。列表标记当前版本与待发布草稿，详情进入“发布与版本”。
- 发布前比较字段、封面、有序途经点和模板条目的变化；必须通过资源校验并填写发布说明，相同内容不能重复发布。
- 首次发布生成 v1，后续发布追加版本，记录内容快照、操作者、时间及说明。
- 历史版本可与当前版本比较。回滚必须填写原因，并将历史内容追加为新版本，不删除历史；存在草稿或资源已下架时不能回滚。
- 放弃修订草稿保留发布内容和历史。下架保留版本；无待发布草稿时可重新上架当前版本，不递增版本号。
- 发布、回滚、放弃草稿和重新上架联动模拟操作日志。版本号校验仅用于会话内陈旧编辑保护，不是服务端并发控制。
- 全部数据仍在内存中，刷新或重置后恢复示例；没有接入真实发布、存储或用户端同步。

## 当前管理员账户

- 左下角身份区或右上角账户图标进入“我的账户”，与管理其他成员的“管理员”和全局“系统配置”分开。
- 显示名称支持校验、保存与未保存离开提醒，同步管理员 A-001、身份区及后续操作日志署名。登录邮箱、管理员编号和所属角色只读。
- 安全页展示示例设备、当前会话、模拟密码重置请求和模拟双重验证状态；敏感动作二次确认并记入 mock 日志。不采集密码、不发送邮件、不绑定验证器、不撤销真实会话。
- 偏好设置的主题使用现有 AppearanceContext，保存在本机；紧凑列表和默认每页条数在本次会话生效。列表上的单次行距和分页调整不覆盖个人默认值。
- 退出后隐藏管理界面，可用演示身份重新进入；本次内存数据保留。刷新仍恢复默认演示身份，不构成真实认证或授权。
- 重置模拟数据同时恢复个人资料、安全状态与列表偏好，不清除本机外观主题。

## 通知中心与我的待办

- 顶栏铃铛打开通知中心并显示未读数量，左侧身份区上方打开“我的待办”；两个视图共用个人工作台抽屉，手机也可通过铃铛切换。
- 通知是发给当前管理员的示例收件箱，与面向 App 用户的“通知公告”模块独立。支持展开正文、单条已读或未读、全部已读、类型与状态筛选、搜索及空状态。
- “全部已读”作用于整个个人收件箱，不限于当前筛选。查看关联记录会将该通知标为已读，但不会完成待办。
- 待办默认按管理员 ID A-001 的负责关系筛选，不等于全站待处理总数。包含审核、举报、反馈、首次资源发布及已完成样例；可切换“我协作”“团队全部”“未分配”，分配变更即时影响归属与计数。
- 任务状态由关联业务记录派生。审核通过或驳回、举报结案或驳回、反馈解决、首次发布成功分别完成任务；发布后的下架不会重新打开首次发布待办。原业务动作仍负责校验、二次确认与审计。
- 截止时间使用明确 UTC 时间，支持逾期筛选；已完成或关联不可用的任务不算逾期。通知已读状态独立于业务完成状态。
- 点击处理会定位到对应模块与记录详情，地址使用 `#/reports?q=RP-102&record=RP-102`，详情可返回个人工作台；关联记录缺失时不会执行业务动作。
- 本轮无实时推送、邮件、浏览器通知授权、任务自动分配或调度服务。通知样例与已读状态在内存中；任务随本次会话的业务数据联动，刷新或重置恢复初始示例。

## 待办分配与协作

- 待办行的“分配与协作”打开独立详情，支持认领、转交、取消分配、协作者、优先级和 UTC 截止时间。保存必须填写说明；没有变化时不能提交。
- 负责人和协作者不能重复，只能选择状态正常的非只读管理员；邀请中、停用和只读成员不能新增到任务。已有失效协作者可移除。
- 当前固定超级管理员可在团队范围调整任务。此资格检查是 mock 交互规则，不是服务端 RBAC，也不代表其他角色的真实授权范围。
- 协作留言与任务变更保留操作者、时间、前后值和通知对象，历史只追加，并联动操作日志。关闭、返回、跳转和刷新有未保存内容保护。
- 通知只写入本次会话内的模拟收件箱，接收人为变更前后的负责人及协作者，排除操作者和非正常成员。其他成员的消息不会进入当前管理员的未读数；没有真实发送或其他身份的登录入口。
- 分配和留言不改变审核、举报、反馈或发布状态。已完成任务锁定分配与计划，但仍可补充留言；关联记录不可用时禁止写入。
- 会话内版本校验拒绝陈旧提交，不替代真实事务或并发控制。刷新和重置同时恢复初始分配、留言与历史。

## 批量分配与逾期提醒

- 待办支持勾选、当前可处理结果全选和半选状态；已完成与关联记录不可用的任务不能勾选。切换范围、状态、类型、搜索或通知视图会清空勾选，不跨筛选保留隐藏任务。
- 批量分配先选负责人并展示逐项预览，再填写说明确认。仅更改负责人，并将新负责人从协作者中移除；其余协作者、截止时间和优先级保留。负责人未变化的任务会跳过。
- 预览列出执行数量、跳过数量及原因。提交前完成所有资格与版本校验，失败时不写入任何任务、通知或审计。成功任务各自追加历史与操作日志，并展示执行结果。
- 已逾期数量按当前可见结果统计；可一键筛选，再勾选任务并手动提醒。提醒仅适用于已逾期、未完成且负责人正常且非只读的任务，未分配或负责人失效的任务会跳过。
- 逾期提醒进入对应负责人的模拟收件箱（负责人是自己时也会收到），类型为“逾期提醒”；协作历史、列表最近提醒时间和操作日志同步记录。提醒不改变业务状态和任务计划。
- 每个任务距上次成功提醒满 24 小时后才可再次提醒，转交或修改截止时间不会清除该限制。完成或延后到未逾期的任务不会再被提醒，历史保留。
- 本轮为手动触发的 mock 提醒，不包含后台定时调度、邮件或系统推送。页面每 30 秒刷新逾期展示；刷新或重置会清除本次会话的提醒记录和限制。

## 后续接入顺序

1. 确认平台资源与私人数据的管理边界，完善管理员登录、服务端授权、MFA、审计和敏感数据脱敏。
2. 先接用户与行程只读摘要、AI 执行摘要；增加真实加载、错误、重试和服务端分页。
3. 设计公共装备、模板、公告与工单模型，再接草稿、审核、发布流程。
4. 为写入增加幂等键、并发版本校验、审计事务、配置版本与回滚；补全未保存修改保护。
5. 最后接通知任务、服务监控、汇总统计与异常告警。AI 失败重试需确认幂等性，当前不提供可能重复修改行程的重试按钮。

真实后台不能仅依赖隐藏按钮或浏览器权限矩阵。所有写操作、批量导出与敏感数据访问都必须由服务端再次授权，并记录审计。Service-role key、供应商密钥和部署凭据不能进入 Web bundle。

本项目 Supabase 自托管约束不变：SQL 使用 `infra/supabase/apply-migration.sh`，Edge Functions 使用 `infra/supabase/deploy-functions.sh`；原型阶段未执行任何迁移或部署。
