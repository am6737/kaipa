# Kaipa 会员与资源保护落地设计

日期：2026-10-08。状态：免费开放阶段的业务接入代码已实现，包含后端、App、访客页、管理后台与发布脚本；未执行实际环境发布，真实支付保持关闭。每用户云存储额度已确定为免费 500 MiB、会员 2 GiB；其他额度为首轮候选配置。尚未完成成本验证或作出对外承诺。

## 1. 已确定的产品边界

- 只有免费版和会员版；会员提供月、年、永久三种购买方式，权益相同。
- 月、年使用订阅商品；永久使用一次性、可恢复的非消耗型商品。
- 免费用户可以完整使用路线、行程、轨迹、装备、清单、基础同行协作和分享。
- 数据数量设宽松上限，防止无限占用；不以刻意卡住普通用户作为转化手段。
- 会员购买更多智能服务和资源额度。首版沿用现有功能，不把尚未实现的离线地图、专业导出等作为已交付权益销售。
- 所有账号，包括永久会员，都受单次输入限制、限流、并发和全站成本保护约束。
- 到期不删除数据、不阻止基础读取、导出、清理及不增加资源的普通编辑。
- 当前优先搭建完整架构，再免费开放观察真实用量；支付先预留适配层，购买入口暂不启用，开放时长暂不确定。
- 会员身份、权益政策、运营阶段独立建模。免费开放不创建虚假交易或永久会员授权，不自动转付费。

| 装备抠图/UTC 自然月 | 30 | 100 | 发起者；分别核算外部服务成本 |

说明：

- 会员有效期间的月度额度仍在每月 UTC 1 日重置，永久会员没有无限 AI 或无限存储。
- 月中升级不重置已用量，只提高当月上限；退款、重新购买、切换年/月不刷新额度。
- AI 完整规划指服务端判定的完整行程/完整装备清单任务；普通澄清和局部修改只用总请求额度。服务端解释任务后、执行昂贵阶段前原子预留子额度，失败时不执行该阶段、不产生半份规划。
- AI 候选值必须结合单次实际成本、失败重试成本和付费人数测算后才能上架。基础数据上限宽松，不代表昂贵第三方服务也可以无限免费。
- 回收站行程继续占数量，避免反复软删除绕过；永久删除才释放。历史快照另外计量和保留，不作为普通活跃对象重复扣数。
- 数据库里的轨迹坐标、文本、attrs 和快照同样占成本；即使没有上传文件也需要单条大小与历史保留限制。
- 装备数、每件图片张数、实际文件大小、账号总存储是四个同时生效的上限，任一达到就阻止对应资源新增。100 件免费装备不承诺每件都能存满 5 张最大图片；总存储还与行程媒体等共享，页面需要明确说明。
- 装备图片以展示和识别为目标，默认不备份原图。候选规格：长边不超过 1,600 px，常见图片压缩目标 300–500 KiB，单张持久化展示图硬上限 2 MiB；透明抠图保留透明通道，按实际字节计量。目标大小不是质量保证，需用文字标签、复杂纹理和透明图样本验证。
- 每用户额度由装备图片、行程照片、视频、缩略图、抠图结果和私有附件等共享，不是每种文件各有一份额度。达到额度暂停新增上传，已有内容继续查看、下载和删除；清理后恢复，不自动收费或删除。
- 以 500 件会员装备 × 5 张 × 500 KiB 估算，装备展示图约 1.19 GiB，超过免费 500 MiB 总存储上限；若每张都达 2 MiB，则约 4.88 GiB，也会触发会员 2 GiB 总存储上限。两项均不含缩略图等派生文件，容量按实际字节计量；存储达到上限仍可添加不带图片的装备，直到装备数量上限。
- 全站容量独立规划，不与单用户额度混淆。例如 1,000 名会员各用满 2 GiB，合计约 1.95 TiB，另需计算免费用户、备份、临时对象及下载流量成本。
- 首版不提高访客单次上传和防攻击阈值来诱导付费。会员也不能用批量邀请或上传影响其他用户。

## 4. 权益与计量数据模型

新增以下领域表，具体字段在迁移时实现，不向客户端开放写入：

| 表 | 核心数据与职责 |
| --- | --- |
| `membership_products` | 稳定的商品 key、渠道、商店 product ID、周期、政策版本；价格从商店返回，金额用最小货币单位 |
| `billing_transactions` | 账号、渠道、交易 ID、原订阅链 ID、环境、商品、支付/撤销时间；渠道+环境+交易 ID 唯一 |
| `billing_events` | 渠道事件 ID、验签结果、处理状态和时间；去重、乱序处理和重试，不在日志记录凭证 |
| `membership_grants` | 来源类型 purchase/gift、来源记录、起止时间、永久标志、承诺政策版本、撤销时间；订阅期限以商店为准 |
| `membership_entitlements` | 私有的真实会员投影：free/member、valid_until、is_lifetime；可重建，不混入开放期体验 |
| `resource_policies` | 不可变版本的功能权限、商业额度、安全硬上限、周期、告警阈值；发布记录和回滚 |
| `operation_campaigns` | draft/scheduled/active/ended/cancelled、适用人群、起止时间、体验政策版本、结束后政策、过渡期与通知计划 |
| `campaign_assignments` | 体验对象、体验起止时间、活动来源；user+campaign 唯一，不代表付费授权 |
| `resource_transition_grants` | 结束时资源基线、冻结上限、收敛上限、过渡到期时间和通知状态；与购买授权分开 |
| `resource_usage` | 额度主体、资源、周期、used、reserved；主体+资源+周期唯一 |
| `resource_reservations` | 预留 ID、用户、业务 request/run/upload ID、额度、状态、租约；业务键唯一 |
| `resource_usage_events` | 追加式 reserve/settle/release/adjust 账本；记录 request ID，不记录私人内容 |
| `upload_tickets` | 发起者、额度主体、授权对象、bucket/path、最大字节、过期时间、状态、实际字节 |

会员信息不放进公开可读的 `profiles`。RLS 仅允许用户读取自己的权益/用量摘要；财务凭证、账本、政策修改仅授予可信后端和有专门权限的管理员。

有效权益计算：任一未撤销、已生效的永久授权或尚未到期的订阅授权即可获得 member；撤销一笔交易不能抹掉其他有效授权。到期按服务端时间即时判断，定时任务用于对账，不作为到期正确性的唯一依赖。

订阅处于取消续费状态时仍可用到付费期末；支付失败、宽限期、暂停、退款、撤销按各渠道确认的状态处理。重复和乱序回调不能简单覆盖一个布尔值，应刷新订阅链的权威状态后重新计算投影。

### 权益解析和运营阶段

统一服务端 `resolveAccess(user, resource, operation, now)`：

1. 读取真实会员授权及承诺版本，得到基础功能和商业额度。
2. 按服务端时间、人群和活动登记读取免费开放体验；体验只能扩展权限，不抵消已有购买承诺。
3. 应用存量过渡规则，区分可读取、可清理和可新增的资源。
4. 校验权限、单次输入、共享限流、并发和全站预算；这些保护不被体验或付费覆盖。
5. 事务内按实际用量+预留判断能否增加资源，返回政策版本、判定依据和可执行动作。

返回真实 `membershipPlan`、`accessSource`（purchase/gift/campaign/free）、`campaignEndsAt`、`transitionEndsAt`、功能权限和各资源有效额度。不要用单个 `isMember` 同时表达身份、体验与所有操作权限。

运营阶段为 `open_access` / `trial_operation` / `paid`，与活动生命周期不同；只改变体验政策与购买入口，不修改身份事实。开放采用独立政策，可开放已交付会员功能及提高观察额度；具体开放额度后续配置，不承诺无限资源。

活动发布必须设定人群、政策版本、安全预算和结束策略：结束时间已确定，或明确暂未确定且将在结束前公告。未定结束时间时仍执行硬上限并定期审查成本，不能产生永久授权。最终安排结束时默认提前 14 天公告并记录通知投递与已读；天数为可配置的运营初始值。

首次符合活动人群的操作在事务中登记体验，客户端不能自选活动 ID 获得权益。结束以服务端时钟为准，不依赖定时任务修改 active 字段。结束/回滚只撤销体验扩展，不撤销购买授权、不删除数据、不自动扣款。

政策发布前预览受影响账号、超额资源、已售承诺和预计成本，记录操作者、原因和生效时间。每次判定记录实际政策版本，便于解释限制和对账，不把不同版本混在一起分析。

### 开放结束的资源过渡

- 正式额度仍为每用户免费 500 MiB、会员 2 GiB；开放额度独立配置，不自动修改正式档位。
- 候选过渡期 30 天：结束时冻结可信资源基线。超额用户的过渡上限取 `max(正式额度,结束时已用量+有效预留)`，不赠送新增空间，不随后续新增抬高基线。
- 过渡期允许清理、导出、普通编辑和在过渡上限内净不增加的替换；清理后上限逐步收敛，不能重新填满已释放的历史高水位。
- 过渡结束后新增按正式额度执行；仍超额的数据保留，不自动收费/删除。基础读取、正常频率下载继续可用，异常公开分享流量仍受保护。
- 结束前已接受的上传票据和 AI run 按预留时政策在原租约内完成；新请求使用当前政策。不重复扣量、不无限延长旧票据。
- 开放期周期 AI 用量不因切换阶段清零；升级只提高上限。明确提示剩余和重置时间，不显示负数余额。

## 5. 数据库写入保护

初期保留现有 hook 的正常调用方式，在数据库加领域级触发器和事务函数，不要求一次重写所有 CRUD。

1. 按资源锁定 `(额度主体,资源,周期)` 计数行，事务内完成校验、业务写入和增减。禁止“先 count 再 insert”的竞态方案。
2. 批量写入按实际新增条目预留；操作失败整体回滚。兼容现有 AI 原子写入、恢复版本、模板复制和批量导入。
3. 归属由业务行和关联关系推导，不能相信客户端传来的 user_id 或 member 标记。阻止未授权改归属；合法转移需要同时检查新旧主体。
4. 删除和不增加资源的编辑在超额状态下仍可执行。增大正文、追加坐标、扩大数组属于资源增加，继续受大小保护。
5. service-role 的后台写入、AI 工具不能默认绕过配额。运营发布的公共路线使用明确的平台资源主体和独立预算。
6. 为 timeline、清单条目、照片元数据、成员、收藏、分类、套装关联和快照也设上限；避免只限制父对象，子对象仍无限新增。
7. 预填存量计数，定时对账与修复漂移；统一多资源锁顺序，避免与已有行程锁形成死锁。

存量用户首次启用时不删除超额数据，使用与开放结束相同的 `resource_transition_grants` 记录一次性基线和过渡期限；清理后逐步收敛，不另外创建无期限的历史高水位上限。

## 6. 文件上传与访客防护

不能只增加一个签名上传接口而继续允许所有旧路径直传，否则用户仍可绕过额度。

- 统一 `uploads.prepare` → 上传 → `uploads.complete`：准备时检查权限并原子预留最大字节，完成时读取可信的对象实际大小结算。
- 使用短时上传凭证和随机固定 path，不允许用户修改 bucket/path 或用别人的行程作额度主体。凭证不出现在日志。
- 优先选择能限制实际上传体大小的一次性网关路径；如果使用 Storage signed upload，必须验证当前自托管版本的大小限制和重用行为。不能假设签名 URL 自带“一次性、指定大小”保证。
- 公共 bucket 保留必要的读取行为，移除宽泛写入策略；仅开放受控票据路径。最终写入、覆盖、删除均校验归属。私有 AI 附件维持私有。
- 普通行程图片候选上限 25 MiB，装备展示图 2 MiB，单个视频 200 MiB，轨迹文件 20 MiB，AI 附件 20 MiB。在网关/Storage 按服务端确定的用途限制实际字节，服务端检查类型；不能只相信 Content-Length、扩展名或客户端 MIME。
- 装备图片客户端先压缩再申请票据，正常流程不上传原图；服务端验证解码尺寸、字节和用途，不能靠客户端自报装备/行程类型逃逸。需服务端处理时，临时输入受独立大小、并发、像素和保留期限限制，不能把处理区变成免费原图仓库。
- 每件 5 张指业务展示图片，张数预留与最终关联也需并发安全；客户端删除图片后服务端清理无引用文件，成功删除实际对象才释放字节。未关联上传、旧图、缩略图、抠图结果仍占总存储；派生图另设生成数量和大小保护。
- KMZ 继续遵循既有解压限制（文档为 15 MB），另限制条目数、压缩比、坐标点数和解析耗时。单条轨迹候选最多 200,000 点；过大时提供简化，不偷偷截断。
- 头像/封面用新对象上传后切换引用，再删除旧对象，避免覆盖路径绕过计量或共享 URL 指向错误内容。额度计算覆盖前后净变化，同时预留上传峰值空间。
- 图片、缩略图、Live Photo 配对视频、封面、装备图、私有附件均计字节。孤儿文件在宽限期后清理；元数据失败不能直接释放已经存在的文件占用。
- 访客查看页面保持方便；访客上传先兑换短期分享会话。校验分享状态与签名会话，不把四位口令当成写权限，不能仅用昵称或可编辑 localStorage 身份授权删除。
- 访客照片计发起人存储；候选每分享每日 500 MiB、单访客会话每日 100 MiB，并结合 IP/会话/分享 ID 限流。归属和速率由服务端判定，攻击升级时才使用挑战验证。
- 上传票据过期后对账：实际存在的对象继续计费或清理后释放，凭证无效且无对象才释放预留，防止迟到上传与清理竞态。
- 公共文件下载还会产生带宽成本；增加缓存、分享维度流量预算及异常热点保护，不能只统计磁盘字节。

## 7. AI 计量与统一防滥用

两套额度并行：用户能理解的请求/规划次数，系统内部的模型/搜索成本预算。内部 token 不作为付费页的计价单位。

- `turn` 在创建 run/job 的同一个事务中预留一次 AI 请求，使用已有 clientRunId/runId 去重；查历史、轮询、取消、重放不扣新的请求额度。
- `execute_job` 必须关联已有预留和有效 lease；新模型调用前检查剩余阶段/整次任务成本预算。重试可以不再扣用户次数，但仍统计实际服务成本。
- 完整规划子额度在服务端识别意图后、研究/生成前原子预留；多次执行同一 run 不再重复扣除。
- 成功结算一次。最终系统失败或取消不消耗用户展示次数，已产生费用保留在内部账本；失败和取消仍消耗请求速率额度，防止反复取消刷免费调用。
- 不能因 metrics 缺失释放所有成本预算：将未知用量保守计入待对账额度，并停止无限重试。
- 月中升级、续费、恢复购买不重置周期计数；额度预留记录周期，跨月完成仍结算原周期。
- 明确单次消息长度、历史窗口、附件数量/大小、工具轮数、搜索次数、任务最大时长和单次成本上界，复用现有超时、租约与重试机制。

候选防护值（免费和会员均受约束）：

| 操作 | 初始保护 |
| --- | --- |
| 普通新增写入 | 每账号 120 次/分钟，导入使用批量事务并按条目计量 |
| AI 新请求 | 每账号 6 次/分钟，最多 1 个正在执行任务、3 个排队任务 |
| 上传准备 | 每账号 60 次/分钟，最多 4 个进行中上传 |
| 分享口令尝试 | 每会话 10 次/10 分钟，结合可信 IP 和分享维度限制 |
| 地图搜索、装备链接解析、识别、抠图 | 独立 endpoint 速率与外部服务日预算；保留现有更严格保护 |

共享计数落在 Postgres 原子函数；边缘网关先做粗粒度流量/请求体保护。高频流量超过数据库承受范围再迁移到 Redis 等共享限流组件，不用进程内存承担唯一保护。

注册/游客创建、认证请求也纳入网关保护。IP 只能取可信代理提供的值；设备信号仅辅助，不能用用户可随意改写的设备 ID 作为唯一身份。避免单 IP 一刀切误伤学校、公司、共享网络。

设置全站模型、搜索、识别、存储/带宽日预算和异常告警，支持按服务熔断。高成本服务不可用时明确提示，基础查看与整理继续可用。会员不享有绕过防攻击规则的特权，也不承诺未实现的优先 worker 调度。

## 8. 支付与订阅落地

采用适配器 `verifyPurchase / handleNotification / refreshSubscription / restorePurchases`，业务权益不绑死某个渠道。

- iOS：月、年为自动续期订阅，永久为非消耗型内购；购买、恢复、服务端交易验证、商店通知均需接入。
- Android：按实际发行渠道选择 Google Play Billing 或国内渠道适配；商店数字权益购买遵循该渠道要求。发行渠道未定前不假设所有 Android 用户都用 Google Play。
- 首版不做 Web 收款、不引导用户绕过应用商店；网页访客保持免费参与。Web 支付未来接入也复用同一权益账本。
- 具体 SDK/聚合订阅服务在确定渠道后选择；目前未发现现成支付依赖，需新增 dev build 验证，不假定 Expo Go 可测试真实内购。
- 用户登录 Kaipa 账号后绑定购买。服务端验证包名、商品、环境、签名、账号绑定与渠道交易状态后才授予权益；客户端成功回调只是线索。
- 同一交易绑定一个 Kaipa 账号，恢复到另一账号时不自动转移，提示切换原账号或通过有审计的支持流程处理。游客购买前提示绑定可找回的身份。
- 沙盒与生产账本隔离，沙盒交易不能授予生产权益；交易重放不能再次延长会员。
- 页面展示商店本地化价格、订阅周期、续费说明和恢复购买入口。价格不硬编码；暂不确定具体售价。
- 月年切换交给渠道确认的生效与折算规则。已有永久会员隐藏新订阅购买；订阅用户购买永久前明确提示原订阅不会自动取消，并提供管理订阅入口。
- 通知短暂不可用时保留已经验证的有效权益；无记录的新购买不能凭客户端声明直接开通。定期与渠道对账修复丢失事件。

永久会员上架前需测算长期负债：商店净收入减退款、获客和预计多年 AI/存储/支持成本，并为已售权益留服务预算。不能为了未来调低成本随意削减已售承诺；政策版本应记录购买时权益，影响既有权益的变更单独评估。

## 9. App 页面、接口与到期行为

新增客户端 `useMembership`（权益）、`useResourceUsage`（摘要），由独立 provider 向“我”、助手、上传入口共享。权益缓存只用于展示，写入授权以服务端为准。

候选 API：

| 接口 | 作用 |
| --- | --- |
| `membership.status` | 返回真实 membershipPlan、validUntil、isLifetime、autoRenew，以及 accessSource、campaignEndsAt、transitionEndsAt、功能权限、各资源 policyVersion 和渠道管理入口 |
| `membership.verify` | 接收购买标识，服务端验真、绑定、投影；限制请求大小和频率 |
| `membership.restore` | 恢复并验证当前账号可绑定的购买，不依据设备本地状态授予权益 |
| `billing-notifications/{channel}` | 渠道验签与事件去重，异步重试和对账 |
| `usage.summary` | 已用/预留/上限/周期重置时间，避免客户端自己统计全库 |
| `uploads.prepare/complete/cancel` | 文件授权、预留、实际字节结算和回收 |

“我”页面展示免费/会员、有效期或永久，进入会员页后月/年/永久三个选项；权益不做三档对比。用量放二级页面，日常界面不反复出现限额营销。

免费开放阶段显示“免费开放中”和已确认的结束信息，用户真实身份仍显示免费或其实际会员状态。购买按钮由独立 `purchase_enabled` 开关控制；未定价或未接真实支付时不展示可点击购买按钮，不用虚构价格测试真实用户。

- 普通数量在 90% 时温和提醒；存储在 80%/95% 提醒；已经到限说明资源、处理方式。
- AI 在剩余较少时显示额度和重置日期，不能运行到一半突然才告诉用户需付费。
- `rate_limited` 返回 429 和 Retry-After，展示“操作较频繁，请稍后再试”，不弹付费页。
- `quota_exceeded` 返回稳定业务错误码、resource、used、reserved、limit、resetAt（若适用）及可执行的清理/等待/升级动作；PostgREST 触发器错误由客户端适配为同一领域错误，不假定能直接控制其 HTTP 状态。
- `service_budget_exceeded` 表示服务暂不可用，不伪装成用户会员不足。不能要求用户付费解决全站故障。
- 到期降为 free，超出的旧数据保留；阻止净增加资源，允许清理和不增加体积的编辑。头像等必要替换按净占用判定，不能因到期彻底无法维护资料。
- 月度剩余额度按当前等级计算，降级后超出免费上限就等重置或续费；不产生负数余额或追加扣款。
- 共享行程以发起人的公共资源额度为准；达到上限时同行者收到明确说明，不诱导每个人购买。
- 退出账号清除上一用户缓存；新登录重新查询；离线仅显示最后确认状态，不允许离线状态伪造服务端额度。

### 多设备与离线同步

- 各设备读取同一服务端用量，本地不独立分配一份额度。客户端预估只用于提示，不能替代最终授权。
- 当前方案不假定 App 已有完整离线新增能力。若后续增加，使用按账号隔离的持久 outbox，保存幂等 request ID、业务版本、依赖对象、待上传文件引用和同步状态。
- 状态区分 pending/syncing/synced/blocked/conflict；同步因到期、活动结束、超额或故障被拒绝时保留本地草稿与文件，标记未同步，允许导出、清理或稍后重试，不能把失败数据当已云端保存。
- 上传先准备票据再传文件；关联写入失败进入回收/重试流程。自动重试有次数、退避和超时限制，不重复占额度。
- 跨设备冲突按业务版本处理，不静默覆盖；批量同步遇到一条额度失败不能删除其他本地内容。账号切换不得把上一账号的草稿/文件同步到新账号，删除本地待同步内容需明确确认。

### 故障和对账

| 故障 | 默认行为 |
| --- | --- |
| 支付渠道/通知不可用 | 已验真的授权按已知有效期继续；新购买显示验证中，不凭客户端开通；恢复后对账 |
| 权益/政策读取失败 | 基础读取继续；只在短期缓存及其真实有效期内使用已确认政策，昂贵新请求无可信授权则暂缓，不能无限沿用会员 |
| 计量/预留服务失败 | 增加资源和昂贵新请求返回暂不可用，不无限放行、不误报用户超额；基础读取保持可用 |
| 文件删除失败 | 保留待清理状态与占用，后台重试；显示“清理中”，不能先释放字节让占用无限增长 |
| 第三方 AI/识别失败 | 用户展示额度按失败规则释放，内部成本保留；基础整理继续可用 |
| 全站预算触发 | 暂停对应新成本操作，保持正常读取与缓存下载；限制异常热点流量，显示服务原因，不弹付费墙 |

“保持读取”指会员与计量机制不新增读取门槛；不能承诺数据库/Storage 自身宕机时仍能读取云数据，离线可读范围取决于实际缓存。

新增定时对账任务：对象实际字节与用量、业务对象与数量、过期预留、无引用文件、渠道交易与授权。任务分批、幂等、可恢复，调整留审计；计量暂时不可用时不把全部未知资源计成零，不自动删除有业务引用的文件。备份/临时对象纳入全站预算，用户用量只计实际归属资源，避免混淆。

## 10. 后台配置与运维

在 `admin/` 增加会员/交易查询、用量、配额政策和异常监控；通过 `admin-api` 的细粒度角色权限操作。

- 人工赠送使用独立授权来源、原因、到期时间与审计，不能改支付交易事实。
- 单用户临时额度覆盖有有效期和审计，不能成为永久绕过保护的开关。
- 配额发布支持预览受影响账号、版本化变更与回滚；并发安全和字节上限不随 UI 开关失效。
- 展示 AI 单次成本中位数/P95、失败重试成本、存储/带宽、人均用量、免费转会员及恢复购买失败率。
- 财务记录按适用留存规则脱敏保存；删除账号释放业务文件和个人用量，不能破坏渠道事件去重和必要财务审计。
- 可配置运营阶段、体验人群、开放政策、结束通知、过渡期限、购买开关与全站服务熔断；预览和审计后发布。修改运营阶段不改变购买身份。

### 免费开放期的统计口径

记录最小必要事件：资源新增/删除、上传成功/失败、压缩前后字节、派生文件字节、AI 请求结果与成本、额度判定、阻止原因、同步阻塞、分享下载流量。事件带请求 ID、运营阶段、真实会员身份、体验来源、政策版本、客户端版本和服务端时间，不采集私人正文、照片内容、精确轨迹或支付凭证。

分析区分普通用户、重度用户、异常账号以及有足够观察时长的活跃账号；不能把刚注册未使用的账号摊入人均成本使数值虚低。同时看 P50/P95/P99、峰值和全站总成本，不只看平均值。被限制/失败的操作单独统计，标注是否有实际上传或解析出大小；未知需求大小不能猜成零。

免费开放数据可帮助确定实际需求、压缩效果、资源分布与成本，不能直接证明付费意愿、收费后留存或永久用户的多年成本。收费转化在购买启用后另行观察。统计保留期、访问权限与用户告知应纳入隐私发布说明。

## 11. 实施顺序与验收

### A：资源保护基础

先做私有政策/计量表、统一权益解析、运营阶段/活动、过渡规则、计数回填、数据库写入保护、共享限流、上传票据和访客保护。先完成可切换的架构，再开始免费开放；开放时长后续决定，普通商业总量采用影子模式观察，权限、文件大小、并发、全站预算和安全硬上限始终执行。

影子模式只记录“本应超过”的操作，监控普通账号 P95/P99、批量导入高峰、存储成本后调整数值。存量回填期间双写账本并对账，避免扫描开始后新增对象被漏计或重复计量。

### B：会员展示与 AI 预算

实现会员/用量摘要、开放期展示、月年永久页面结构、到期/过渡/超额状态、AI 原子预留、成本熔断和支付适配接口。购买暂不启用；测试环境使用可审计赠送验证会员，不把本地按钮当真实支付。免费开放记录成功与被阻止的用量，后台可预览结束影响。

### C：真实支付与运营

后续根据免费开放数据确定成本与其他候选额度，再按发行渠道接真实支付，完成沙盒购买、通知、恢复、退款和生产对账。价格与对外权益发布后才启用购买；按公告结束体验、执行过渡，不强迫原用户付款。现阶段不要求先做真实支付或付费试验。

核心验收用例：

1. 同账号最后一个空位被多个并发新增争抢，只允许一个成功；批量失败无残留计数。
2. 直接调用 PostgREST、RPC、Storage 及 AI worker 均不能绕过归属和额度；测试 authenticated、anon、service-role 各入口。
3. 重复请求、worker 恢复、重复通知、乱序退款不重复扣次数、不重复授权、不误撤其他购买。
4. 上传失败、迟到完成、重复 complete、覆盖、孤儿回收、伪造文件大小和访客恶意上传计量正确。
5. 到期超额不删除数据，仍能读取、导出、清理、普通编辑；跨月结算、月中升级与续费不刷新用量。
6. 共享参与者不误扣自己的行程数；公共与个人清单、访客字节归属正确。
7. 测试账号无法伪造会员字段、恢复他人交易或用沙盒凭证激活生产会员；注册刷号触发保护。
8. 全站成本熔断不影响基础读取；限流清楚显示等待时间，AI 系统失败可退展示额度但无法无限刷调用。
9. 明暗模式检查免费/会员、加载、购买处理中、验真延迟、恢复失败、到期和超额界面。
10. 免费开放不生成支付交易/永久授权；人群不能伪造，活动结束和回滚不撤销真实购买，未启用购买时服务端也拒绝新购买入口操作。

初始防滥用配置可由后台调整：

| 保护 | 初始值 | 口径 |
| --- | ---: | --- |
| 全站存储容量 | 20 GiB | 所有 Storage bucket 的已记账对象，包含平台图片缓存 |
| 全站文件对象数 | 500,000 | 极小/空文件也占对象名额 |
| 每账号文件对象安全上限 | 50,000 | 真实对象数，独立于会员商业额度 |
| 全站每日上传准入 | 50,000 | 失败/取消的已准入上传也保留请求预算 |
| 每账号每日上传准入 | 5,000 | UTC 自然日，不是终身上传次数 |
| 全站每日上传字节准入 | 20 GiB | 失败或未确认上传保守保留成本预算 |
| 每账号每日上传字节准入 | 2 GiB | 清理历史文件不无限刷新日预算 |
| 每账号同时上传 | 4 | 10 分钟有效凭证；过期取消后迟到上传拒绝 |
| AI 并行 run | 4 | 每账号，所有档位一致 |
| 模型预算 | 20,000,000 / 日；400,000 / run | token 安全单位，不是人民币价格 |
| 图片/链接服务请求预算 | 10,000 / 日；50 / 账号日 | 不因供应商失败退成本预算 |
| 地图请求预算 | 100,000 / 日；1,000 / 账号日 | 保留原有更细的功能限流 |

装备新图片最多 5 张、单图最多 2 MiB；客户端按最长边 1,600 像素压缩，普通照片优先接近 500 KiB，透明 PNG/WebP 保留透明度。使用独立 gear bucket，共享账号总存储。既有超限数据不自动删掉，允许不增量编辑和清理。

`resources` Edge Function 提供上传准入/取消、访客打开/读取/新增/删除、管理员查看/配置、维护及明确拒绝购买的接口。客户端不能决定资源归属、有效权益或实际文件大小。直接 PostgREST、Storage 和 service-role 业务写入仍由数据库触发器控制。

Storage 在权限探测时回滚 INSERT，真正完成上传时会用可信数据库角色写 metadata。因此配额结算在数据库触发器中读取服务端 measured size，不依赖 RLS 或客户端回调。头像/封面替换使用新路径，不允许通过 upsert 绕过预留。删除经 Storage API，成功删除 metadata 才释放账本；底层物理清理可能异步，磁盘临时对象及备份需要独立运维监控。

访客不再直接读取可枚举的邀请码表或匿名写入。服务端验证分享码，发放随机会话令牌，保存哈希；上传计分享发起人，删除依赖 `guest_session_id`，同名访客没有互删权限。浏览器按分享链接保存令牌，使用正确分享码可续期同一会话；清空浏览器存储不会凭昵称获得旧内容删除权。

识别、抠图、装备链接、地图、账号升级与 QR 接口都有共享保护。AI 在每次供应商调用前预留输入与输出预算，输出最多 8,192 tokens；图片按保守像素额度估计，不能误把 base64 当作文本 token。SDK 隐式重试关闭，每次任务重试仍经预算准入。未知供应商消耗保留预留；有 usage 时结算，用户次数在 run 成功/失败时结算或释放，同一 run 恢复不重复扣量。参考 [OpenAI 官方重试指导](https://developers.openai.com/api/docs/guides/rate-limits#retrying-with-exponential-backoff)，并核对安装版本的 `maxRetries: 0`。

现有本月成功 AI run 和可识别规划记录回填；安装前已接收的在途 run 单独预留，不拒绝已接受的旧任务。无法重构的历史识别/抠图调用不追溯扣量，App 显示计量开始时间。购买、赠送、升级和活动切换均不重置自然月用量。
